# 留光 · LUMEN 網站維護指南

> 最後整理：2026-09-08。這份文件以目前專案程式為準，提供日後更新內容、加入作品、執行測試與部署時查閱。

## 1. 網站用途與技術選擇

這是一個朱芸的個人作品集網站，品牌名稱為「留光 · LUMEN」。網站主要包含：

- 個人履歷式介紹與手作背景
- 網頁／前端作品列表與作品詳細頁
- 水晶花、皮件、布製品等手作作品列表與詳細頁
- 保留原始互動的課堂作業展示頁

| 項目 | 目前使用方式 |
| --- | --- |
| 前端框架 | Vue 3，使用 Composition API 與 `<script setup>` |
| 建置工具 | Vite 8 |
| 路由 | Vue Router，使用乾淨網址的 History 模式 |
| 狀態工具 | Pinia 已安裝並在入口初始化；目前正式頁面沒有使用 store |
| 樣式 | 原生 CSS；各 Vue 元件多為 `scoped` CSS |
| 字型 | 專案內的 Chiron 中文字型，並由 `src/assets/main.css` 載入 |
| 部署 | GitHub Pages，自動建置並發布 `dist/` |

## 2. 開始前：環境與常用指令

### 必要環境

- Node.js：專案要求 `^22.18.0` 或 `>=24.12.0`；建議使用 CI 相同的 **Node.js 22.18.x**。
- npm：使用專案內的 `package-lock.json` 固定依賴版本。

第一次安裝或想依 lockfile 乾淨重裝時，在專案根目錄執行：

```sh
npm ci
```

日常開發、正式建置與預覽指令如下：

```sh
# 開發伺服器；預設通常是 http://localhost:5173/
npm run dev

# 產生正式網站到 dist/
npm run build

# 預覽「已建置」版本；先執行 npm run build
npm run preview
```

`dist/` 是自動產生的正式檔案，已被 `.gitignore` 忽略；不要手動修改或提交它。

本專案尚未設定 ESLint、單元測試或 E2E 測試指令，因此每次修改後，最低限度請執行 `npm run build`，再用瀏覽器檢查頁面。

### 建議的日常維護流程

1. 先查看目前變更：`git status`。
2. 開啟開發伺服器：`npm run dev`。
3. 修改內容、圖片或元件。
4. 檢查首頁、認識我、網頁作品、手作日常與至少一件詳細頁。
5. 執行 `npm run build`，確認沒有編譯錯誤。
6. 確認差異：`git diff`、`git diff --check`。
7. 確認無誤後再 commit、push 與建立／合併 Pull Request。

若要新增套件，使用 `npm install <套件名稱>`，並一起提交 `package.json` 與 `package-lock.json`；不要手動修改 lockfile。

## 3. 專案架構

```text
vue-portfolio/
├─ .github/workflows/deploy-pages.yml   GitHub Pages 自動部署流程
├─ public/                              原樣複製到正式網站的靜態檔案
│  └─ classwork/                        課堂作業 HTML、CSS、JS 與其圖片
├─ src/
│  ├─ main.js                           建立 Vue App、掛載 Pinia 與 Router
│  ├─ App.vue                           全站外框、開場動畫、游標／回頂端效果
│  ├─ router/index.js                   網址與頁面對應
│  ├─ views/                            路由頁面
│  ├─ components/                       可重複使用的元件
│  ├─ data/projects.js                  所有作品資料與圖片載入規則
│  ├─ img/                              由 Vite 打包的本機圖片
│  ├─ assets/main.css                   全站色彩、字型與基礎樣式
│  └─ assets/handmade-buttons.css       手作分類按鈕的共用樣式
├─ docs/                                維護文件
├─ package.json                         指令、相依套件與 Node.js 要求
└─ vite.config.js                       Vite 與 GitHub Pages 子路徑設定
```

網站的主要資料流如下：

```text
瀏覽器
  → src/main.js（建立 App、Pinia、Router）
  → src/App.vue（全站 Header / RouterView / Footer）
  → src/router/index.js（選擇頁面）
  → views 與 components（顯示畫面）
  → src/data/projects.js / src/img / public/classwork（作品內容與圖片）
```

## 4. 頁面、網址與負責檔案

| 網址 | 頁面／元件 | 用途與維護位置 |
| --- | --- | --- |
| `/` | `src/views/HomeView.vue` | 首頁介紹、精選作品、聯絡區塊 |
| `/about` | `src/views/AboutView.vue` | 朱芸的履歷式自我介紹、技能與手作背景 |
| `/web-projects` | `src/views/ProjectListView.vue` | 網頁作品列表；由 `type: 'web'` 驅動 |
| `/handmade` | `src/views/ProjectListView.vue` | 手作作品列表、分類與子篩選 |
| `/projects/:id` | `src/views/ProjectDetailView.vue` | 依作品 `id` 顯示詳細資訊 |
| `/classwork/...` | `public/classwork/` | 獨立的課堂作業原始頁面 |

導覽列位於 `src/components/SiteHeader.vue`，頁尾位於 `src/components/SiteFooter.vue`。新增內部頁面時，請同時：

1. 新增 `src/views/新頁面.vue`。
2. 在 `src/router/index.js` import 並加入 route。
3. 視需要在 `SiteHeader.vue` 加入 `<RouterLink>`。
4. 以 `npm run build` 測試。

內部連結請使用 `<RouterLink>` 或 `router.push()`，不要寫成 `<a href="/about">`。這個專案正式環境有 `/vue-portfolio/` 子路徑，硬寫根目錄連結會在 GitHub Pages 指到錯誤位置。

`index.html` 管理瀏覽器分頁顯示的基本資料：

- 網頁語言：`zh-Hant`
- 網頁標題：`留光·LUMEN — 前端與手作作品集`
- 搜尋引擎描述：`留光·LUMEN 的前端與手作作品集`
- 分頁圖示與 Apple 圖示：`src/img/LOGO.png`

若要改作品集名稱、更新 SEO 描述或換圖示，請修改 `index.html`。換圖示後建議使用 PNG 方形圖片，並重新建置後以無痕視窗確認，避免被瀏覽器快取舊圖示。

## 5. 全站外框與視覺效果

### `src/App.vue`

所有路由都被包在同一個 App 外框中：Header、`<RouterView>` 與 Footer。這裡同時管理幾個全站效果：

- 初次載入會顯示約 3 秒的「筆記本打開」動畫；可按「略過動畫」。重新整理後會再次顯示，因為目前沒有記住已看過的狀態。
- 桌機游標移動時，首頁顯示花瓣碎片，其他頁面顯示水晶碎片；觸控裝置與系統要求減少動態效果時不會觸發。
- 捲動後會依頁面顯示不同造型的「回到頂端」按鈕：網頁作品是像素藤蔓，手作分類是材質圓點，其餘頁面是植物藤蔓。
- `ProjectListView.vue` 會發出 `handmade-category-change` 自訂事件給 App，用來讓回頂端按鈕知道目前是水晶花、皮件或布製品。

不要只改 `ProjectListView.vue` 的分類名稱。若新增手作大分類，還要檢查 `App.vue` 中與分類相關的顏色／回頂端樣式判斷。

### 全站設計 token

`src/assets/main.css` 定義主要 CSS 變數：

```css
--cream: #f8f6f0;
--ink: #292820;
--muted: #706d63;
--terracotta: #bf654c;
--peach: #eac39f;
--sand: #ede8dc;
```

## 6. 個人履歷與聯絡資訊的更新

### 認識我頁面

目前所有個人履歷內容直接寫在 `src/views/AboutView.vue`，包括：

- 姓名、出生年、星座、學歷與培訓期間
- 至誼實業與主富服裝的工作時間與職稱
- UI/UX 與前端技能
- 布包、皮件與水晶花作品的來源說明

要更新文字時，直接修改此檔案 template 中對應的段落、個人資料卡、時間軸卡片與技能 `<li>`。同一項資料若出現兩次（例如學歷同時在資料卡與時間軸），請一併更新，避免日期不一致。

### 放入個人照片

目前認識我頁面顯示 `YOUR PHOTO` 佔位設計。照片準備好後，建議：

1. 建立 `src/img/profile/`，將照片放入，例如 `src/img/profile/zhuyun.jpg`。
2. 在 `AboutView.vue` 的 `<script setup>` 加入：

   ```js
   import portrait from '../img/profile/zhuyun.jpg';
   ```

3. 將 `.photo-placeholder` 內的文字替換為：

   ```vue
   <img :src="portrait" alt="朱芸個人照片">
   ```

4. 在該頁 scoped CSS 加上：

   ```css
   .photo-placeholder img {
     position: absolute;
     inset: 0;
     width: 100%;
     height: 100%;
     object-fit: cover;
   }
   ```

照片會隨 Vite 正式打包；請使用清楚、裁切接近直式的照片，並先壓縮檔案大小。

### 首頁與聯絡方式

- 首頁文字、首圖與精選區都在 `src/views/HomeView.vue`。
- 首頁聯絡區目前的 Email 是 `hello@example.com` 範例值；公開履歷前務必替換為真正可收信的 Email，或移除該連結。
- Facebook 與 Instagram 連結也在同一聯絡區。
- 首頁首圖目前使用 Unsplash 外部圖片。若要避免外部圖片失效或授權不明，建議改用 `src/img` 下自己擁有的圖片並透過 import 載入。

## 7. 作品資料的核心：`src/data/projects.js`

這個檔案是作品目錄的單一來源。作品卡、首頁精選、列表、詳細頁與前後作品導覽都從這裡讀取資料；請不要在畫面元件內硬寫新的作品卡。

### 一般作品資料欄位

```js
{
  id: 'unique-project-id',           // 必填且公開後不要隨意改名
  type: 'web',                       // 'web' 或 'handmade'
  category: 'leather',               // 手作作品必填：crystal-flower / leather / fabric
  level: 'junior',                   // 僅水晶花使用
  title: '作品名稱',
  year: '2026',
  description: '作品介紹',
  tags: ['標籤一', '標籤二'],
  imagePaths: ['leather/example-01.jpg'],
  materials: '材料名稱',             // 手作作品常用
  learningFocus: '學習重點',         // 網頁作品常用
  demoUrl: 'https://example.com',
  githubUrl: 'https://github.com/...',
  embedUrl: 'classwork/example.html',
  embedHeight: 900,
  collaboration: { label: '專案類型', role: '個人分工' },
  hidden: false
}
```

欄位不一定全部需要，但應至少填入唯一 `id`、`type`、`title`、`year`、`description`、`tags`，以及適合的圖片或 `cover`。

重要規則：

- `id` 會形成 `/projects/:id` 網址。公開後改名會讓舊連結失效。
- `hidden: true` 會從列表與首頁精選中隱藏，也會讓詳細頁視為找不到作品。
- `imagePaths` 的第一張會成為作品卡封面；詳細頁會依順序顯示全部圖片。
- `embedUrl` 存在時，詳細頁會嵌入 iframe，而不是使用圖片輪播；設定 `embedHeight` 避免被截斷。
- `demoUrl` 是「查看網站」按鈕；`githubUrl` 有值且不是 `#` 時才會顯示 GitHub 按鈕。

### 本機圖片的正確方式

檔案開頭使用：

```js
import.meta.glob('../img/**/*.{jpg,jpeg,png,webp,avif}', {
  eager: true,
  import: 'default'
});
```

所以作品圖片必須放在 `src/img/` 下，並在資料中使用相對路徑：

```js
imagePaths: ['flower/junior/junior-01-1.jpg']
```

不要使用下列寫法：

- `'/src/img/...'`
- `http://localhost:5173/...`
- 電腦完整檔案路徑，例如 `C:\\Users\\...`

這些路徑在 GitHub Pages 正式環境不會正常運作。圖片副檔名若不是 JPG、JPEG、PNG、WebP 或 AVIF，要先擴充 `import.meta.glob` 的副檔名清單。GitHub Pages 在 Linux 環境部署，檔名大小寫必須完全相同。

更多案例請參考 [作品圖片管理筆記](作品圖片管理筆記.md)。

### 網頁作品與課堂作業

網頁作品資料由檔案前段的 `classworkProjects` 管理。課堂作業原始 HTML、CSS、JS 放在 `public/classwork/`，例如：

```text
public/classwork/clinic-queue.html
public/classwork/loading-animation/index.html
```

`public/` 下的檔案會不經 Vite 處理直接複製到 `dist/`。`projects.js` 使用：

```js
const classworkBase = `${import.meta.env.BASE_URL}classwork/`;
```

因此資料應持續使用 `${classworkBase}檔案路徑`，不要寫死 `/classwork/...`；前者在本機與 GitHub Pages 子路徑都能正確運作。

首頁與網頁列表的排列先由 `featuredClassworkProjectIds` 決定，沒有列出的網頁作品才接在後面。想調整首頁網頁作品順序時，優先調整這個 ID 陣列。

### 手作作品

手作資料分三種：

| 類型 | 圖片資料夾 | 資料位置與規則 |
| --- | --- | --- |
| 水晶花 | `src/img/flower/<level>/` | 在 `crystalFlowerDrafts` 新增資料；圖片名稱依 `prefix-編號-1.jpg`、`prefix-編號-2.jpg` 自動尋找 |
| 皮件 | `src/img/leather/` | 在 `projects` 陣列中的皮件資料區手動新增一筆 |
| 布製品 | `src/img/fabric/` | 在 `projects` 陣列中的布製品資料區手動新增一筆 |

水晶花層級標籤由 `crystalFlowerLevels` 管理，皮件篩選標籤由 `leatherTypes` 管理。首頁手作精選順序由 `handmadeFeaturedProjectIds` 控制，不會自動依資料新增順序改變。

新增手作大分類時，至少同步檢查：

1. 新作品的 `category` 值。
2. `ProjectListView.vue` 的 `handmadeCategories` 與對應篩選 UI。
3. 網址 query 參數的讀取與驗證。
4. `ProjectCard.vue`、`ProjectDetailView.vue` 返回列表時是否保留該分類。
5. `App.vue` 是否需要新增此分類的回頂端按鈕樣式。

分類網址範例：

```text
/handmade?category=crystal-flower&level=junior
/handmade?category=leather&leatherType=chrome-tanned
/handmade?category=fabric
```

更多背景請參考 [作品分類導覽筆記](作品分類導覽筆記.md)。

## 9. 正式建置與 GitHub Pages 部署

### 現有部署設定

- GitHub 遠端倉庫：`https://github.com/Yun-1013/vue-portfolio.git`
- 部署 workflow：`.github/workflows/deploy-pages.yml`
- workflow 會在 **push 到 `main`** 時執行，也可在 GitHub Actions 手動執行。
- workflow 使用 Node.js 22.18.0，執行 `npm ci`、`npm run build`，再上傳 `dist/` 到 GitHub Pages。
- 專案目前 `vite.config.js` 的正式 `base` 是 `/vue-portfolio/`，對應 repository 型 GitHub Pages 的子路徑。

一般部署流程：

```text
本機完成修改與 npm run build
  → commit 到工作分支
  → push 到 GitHub
  → 建立 Pull Request 並合併到 main
  → GitHub Actions 自動建置與部署
  → 到 Actions 確認 Deploy to GitHub Pages 成功
```

目前 workflow 不會因 push 到其他分支而自動部署。因此工作分支（例如 `0902-3`）的 push 只會上傳原始碼；必須合併／push 到 `main`，或在 Actions 手動觸發 workflow，才會更新公開網站。

### Repository 名稱或網域更動時

若 GitHub repository 改名，請同步修改 `vite.config.js`：

```js
base: command === 'serve' ? '/' : '/新的-repository-名稱/'
```

若改用自訂網域且網站放在網域根目錄，通常會改為：

```js
base: '/'
```

修改 `base` 後一定要重新 `npm run build`，並檢查圖片、CSS、課堂作業與所有連結是否正常。

### 重要：乾淨網址的直連限制

目前 Router 使用 `createWebHistory()`，網址好看，例如：

```text
/about
/web-projects
/projects/waterpark-team-project
```

但 GitHub Pages 是靜態主機，沒有 SPA rewrite 設定；目前專案也沒有 `public/404.html` fallback。這表示在公開站上直接開啟或重新整理 `/vue-portfolio/about`、`/vue-portfolio/projects/...` 等非首頁網址時，**可能出現 404**。

因此：

- 將履歷連到首頁時，先在公開網站測試各導覽連結。
- 若要把 `/about` 直接放在履歷中，請先實作並測試 GitHub Pages 的 SPA 404 fallback，或改用 Hash Router（網址會變成 `/#/about`），或改部署到支援 SPA rewrite 的平台。
- 不要只靠本機 `npm run dev` 判斷直連是否安全；本機開發伺服器會自動提供 SPA fallback。

## 11. 常見問題與處理方向

| 現象 | 優先檢查 |
| --- | --- |
| 本機有圖、正式站沒有圖 | 圖片是否在 `src/img`、`imagePaths` 是否正確、檔名大小寫與副檔名是否一致 |
| 詳細頁找不到作品 | `/projects/:id` 的 `id` 是否存在；作品是否被設為 `hidden: true` |
| 新作品沒有出現在首頁 | 檢查 `hidden`；首頁精選是否由 `featuredClassworkProjectIds` 或 `handmadeFeaturedProjectIds` 固定控制 |
| 課堂作業 iframe 空白或 404 | 檢查檔案是否真的在 `public/classwork/`，以及 `embedUrl` 是否以 `classworkBase` 建立 |
| 手作返回列表回錯分類 | 檢查 `category`、`level`／`leatherType` query 與資料設定 |
| GitHub Pages 圖片與 CSS 路徑錯誤 | 檢查 `vite.config.js` 的 `base` 是否仍為正確 repository 路徑 |
| 重新整理認識我或詳細頁後 404 | History Router 的 GitHub Pages 直連限制；需加入 fallback、改 Hash Router 或改部署平台 |
| 公開網站沒有更新 | 檢查是否已合併到 `main`，再查看 GitHub Actions 的部署結果 |

## 12. 不要隨意刪除的項目

- `package-lock.json`：確保 GitHub Actions 與本機使用相同依賴版本。
- `src/assets/fonts/chiron/`：全站中文顯示所需字型資源。
- `src/data/projects.js` 的圖片載入與正規化邏輯：它讓第一張圖片變成卡片封面、全部圖片進入詳細頁輪播。
- `public/classwork/` 內各作業的相依 CSS、JS、圖片：獨立 HTML 常以相對路徑互相引用，刪除其中一個檔案可能造成作業壞掉。
- `.github/workflows/deploy-pages.yml`：GitHub Pages 自動部署設定。

`src/stores/counter.js` 是 Pinia 的範例計數器，目前沒有被正式頁面使用。若日後要清理它，先以 `rg "useCounterStore" src` 確認仍沒有任何元件使用，再刪除；Pinia 本身已在 `src/main.js` 初始化。

若要做大型改版，建議先建立新分支、保留可正常部署的版本，並在每一個階段執行 `npm run build`。
